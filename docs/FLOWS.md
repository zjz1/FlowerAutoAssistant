# 《小花仙》挂机助手 · 文字版流程手册

本文档是**全项目各模块/各功能的文字版流程手册**，权威参考，供代码审查、功能交接、开发排期使用。

## 约定（重要）

1. 每个模块 / 功能在本文档中对应**一节**，内写清：目标、入口、步骤串、关键兜底/踩坑点。
2. **今后项目新增任何功能，必须在本文档的对应模块章节下追加一条文字版流程**，与代码、`PROGRESS.md`、JSON 任务链同步更新。
3. 同一功能若同时存在「JSON 任务链实现」与「引擎内实现（如好友采粉）」，两者都写。
4. 识别体系全局三通道：OCR 文字定位 → HSV 颜色定位（纯图形按钮）→ 坐标锚点/模板匹配兜底。

## 0. 全局编排（daily.json）

入口：`run_daily`（引擎层）。

按固定顺序调度 **7 大模块**（2026-10-06 里程碑 79 起：签到并入启动），**每个模块都是可选（required:false）**。容错由各模块 `on_fail` 决定：
除 `startup` 为 `stop_round`（失败即终止本轮）外，其余模块失败仅跳过（`on_fail:skip`）：
> **`startup` 必须 `stop_round`（2026-10-03 里程碑 69）**：登录/切号没做成时若继续跑后续模块，就会
> 在登录页/错误账号上「空跑一整轮」并产出一堆假结果（2026-10-03 实测：切号失败 → 误点「登录」→
> 公告/进入游戏/收尾守卫全部空转，用户看到的正是「影响后续的全部检测」）。

`开始启动(登录+可选切号+签到, 里程碑 79 并入) → 种植 → 社交(含闪耀委托挑战+好友采粉+社区点赞+矿洞探险) → 体力 → 每日任务 → 领取奖励(在线礼包+花灵派对+奇妙花宝) → 挂机`

每一步骤边界可协作式中断（`request_stop()` / `stop_requested()`），用于「停止当前流程但不关闭服务」。

## 1. 开始启动 / 登录（flow_startup.json）

目标：登录进游戏；可选切换账号；**签到（2026-10-06 里程碑 79 决策 D 并入，原 flow_signin.json 已删除）**。

1. `if_config(enable_switch=true)` 可选切号 —— **全链 fail-safe（里程碑 69 起，里程碑 74 实机重修）**：
   - **同号跳过**（里程碑 74，`if_account_tail`）：登录页中央恒显示**当前选中账号**掩码（实测 `186****61`@rel(0.508,0.395)），
     尾部 == `target_tail`（config.target_tail）时 `then` 为空 —— 什么都不做、直接落到「登录」，**不开切号 UI**。
     尾部解析与 `click_account_tail` 同一套（尾部数字 + `****` 校验，不误认普通数字块）；未命中走 `else` 进切号链。
   - 不同号 → `click_template('b1_switch_down.png', threshold=0.8, region_rel=[0.68,0.30,0.88,0.50], abort_on_fail=true)`（里程碑 76 删 `fallback_rel`，模板未命中即如实中止）：
     **入口 = 账号行右端的灰色向下箭头 ˅**（= 该模板本体），实测 rel(0.7745,0.3995)；默认 `sqdiff` 全尺度 score 0.99+ 精确命中、全图无假阳性。
     ⚠ **旧链点的是右缘功能菜单列的「切换」（公告/找回/客服同列），不是切号按钮**（2026-10-03 用户指认 + 实机定位）。
   - `click_account_tail` 按 `target_tail` 在**中央账号纵列** `region_rel=[0.30,0.30,0.80,0.90]` 内匹配并点击
     （`abc****de` 尾号匹配；旧区域 `[0.80,0.03,1.0,0.65]` 在右缘，列表展开后也盖不住 → 当晚失败第二根因），`abort_on_fail=true`。
   - **`abort_on_fail` 是本链的核心**：认不到入口、点不到目标账号，就如实中止 `startup`
     （由 `fail_flow` / `FlowFailed` 机制回收成 `"fail"`），**绝不带着错误账号继续去点「登录」**
     （用户 2026-10-03 决策：宁可当天不跑，也不能用错误账号跑完当天全部任务）。
   > **2026-10-03 故障复盘（里程碑 69）**：「切换账号」旧坐标 rel(0.773,0.394)→绝对(989,283) 在改版后正好落在「登录」按钮上；
   > 而该坐标是历史 `fallback` 条目**自我强化**出来的（认不到 → 盲点 → 盲点坐标又被写回知识库 → 下次继续盲点）。
   > 三处引擎修复：① `_log_click` 对 `method=="fallback"` **一律不落库**；② 回退查找**跳过** `method=="fallback"` 的历史条目；
   > ③ 新增 `no_fallback`（禁用整条缓存回退）。同时把 `登录界面` 里已失效的「切换账号」anchor 条目改名置为
   > `method=disabled`（`data/click_log.json`），使其退出可复用键名。
   > **里程碑 74 实机重修**：上面的「点右缘『切换』」本身就用错了控件 —— 真正的切号入口是**账号行右端 ˅（`b1_switch_down.png` 模板本体）**，
   > 账号列表是**中央纵列**（行距≈0.105）。故本链改走「`if_account_tail` 同号跳过 → 模板切号入口 → 中央列按尾号点」，
   > `no_fallback`（禁止一切回退）降级为**仅 `abort_on_fail`**（同日实测坐标曾作 `fallback_rel`；**里程碑 76 按新规则删除** —— 直接坐标一律禁止，模板未命中即如实中止）。
   > 实机定位均经用户指认 + adb 只读截图 + 授权代点 1 次验证；若登录页再改版，模板失效 → `abort_on_fail` 如实中止。
2. `if_text(登录)`：若屏幕有「登录」文字 → 点「登录」。
3. **公告 + 进入游戏重试循环（里程碑 79 决策 A1 重构）**：**删除原「已在主界面?」预检**（点完登录必然还要点
   『点击进入游戏』，预检在登录界面只产出 MISS 日志属纯浪费；自动进入游戏的罕见情况由循环未命中 + 后续
   `wait_scene` 兜住）；轮数按用户定值 **8→3**（约 15s 覆盖，迟到公告由第 6 步收尾脱困 `close_dialog` 兜底，不再靠拉长轮数硬等）。
   `retry_loop(max_rounds=3)` 每轮：`if_text(公告页签 ['版本公告','维护公告','防诈骗提示'])` →
   `click_template(close_online_small.png, th0.85, region [0.80,0.05,0.92,0.20])` 关公告
   （实测 score=1.000 @rel(0.8625,0.1333)；里程碑 76 删 fallback_rel）→
   `if_text(['点击进入游戏','进入游戏'])` → `click_text(mark:true)`。
   > ⚠ **不能拿「公告」当锚点**：关键字是子串匹配，`locate('公告')` 会撞上「版本公告」——实测落在 (199,180)，
   > 即版本公告那一行。这也是本项目「锚点文字必须唯一」的又一例证。
4. **到位守卫 `wait_scene` 场景列表（里程碑 79 决策 B/C；里程碑 80 A/B 语义修正）**：
   `wait_scene(scene=["户外主界面","签到中"], timeout=10)` —— 点完「进入游戏」有两种终态：
   **A** 今日未签到 → 签到窗先弹出（可盖住底栏）；**B** 今日已签到 → 户外主界面（底栏可见）。
   故等待写成**场景列表**：任一场景命中即成功、谁先出现走谁（签到窗可见 = 启动成功，等价于跳过底栏判断
   直接进第 5 步签到段）；已签到则底栏正常匹配（10s 足够）。引擎侧：一帧截图多场景共用（每场景一次 OCR，
   不逐场景重截屏），单场景调用点行为逐字节不变。
   > **里程碑 80 消除的已知边界**：里程碑 79 时若签到窗盖住底栏，单选「户外主界面」会超时登记软失败 →
   > `stop_round` 中止整轮（16:35 实弹）。场景列表 + scenes.json 新增「**签到中**」（`any[点击签到]`，
   > 签到面板主按钮文本、不随页签活动名轮换、当日已签不弹窗故无误报面）后该边界消除；
   > **原「静默等待」引擎变体需求就此关闭**。成功日志为 `[等待成功] 场景『X』(多场景任一命中)`。
   未到位 → `close_dialog` 脱困 → 补点「进入游戏」→ 再 `wait_scene` → 再 `if_scene` 复核，两轮脱困结构不变，
   仍不进**如实报出**。
5. **签到部分（里程碑 79 决策 D，原 §2 整段迁入）**：`sleep 2s`（签到窗实测进入游戏后 ~10s 内弹）→
   `if_text('点击签到')` 命中（=当日未签且启动成功）：`retry_loop(3)` 点「点击签到」（mark 命中即停，
   整轮无命中自动 close_dialog 脱困重试）→ `wait_text(['点击任意处关闭','点击任意处','恭喜获得'], 5s)` →
   点文字关闭奖励框 → `close_dialog(corner/corner_white)` 退签到界面 → `if_scene('户外主界面')` 归位复核，
   未归位脱困一次再复核。当日已签「点击签到」MISS 天然跳过。
6. **收尾复核（里程碑 79 决策 C）**：`if_scene('户外主界面')` 未归位 → 脱困两轮（`close_dialog` +
   补点「进入游戏」+ `wait_scene`），仍不行**如实放弃**（后续模块自带归位链）。

> 登录界面**曾**按「尺寸固定、不随分辨率变化」处理，故旧版切号用「锚点 + 颜色 + 账号尾号匹配」而不给整屏相对坐标。
> 2026-10-03 登录页改版后这些锚点/颜色/坐标全部失效：现在只保留**区域限定（`region_rel`，仅作搜索窗口）**与
> 实时识别（OCR/模板）。里程碑 69 曾用 `no_fallback=true` 完全禁止回退；**里程碑 74 实机重修后**改为「模板入口 +
> `abort_on_fail` 兜底」（同日实测坐标作 `fallback_rel`，非历史自我强化坐标；**里程碑 76 起该 fallback 已按新规则删除**）—— 认不到入口/点不到账号仍**如实中止本轮**。

## 3. 种植 / 花田（flow_plant.json）

目标：进入自己家园（并为后续模块提供「已在家园」的归位能力）。

0. **整段守卫**（2026-09-29 里程碑 56；**里程碑 80 判据迁移**）：`if_scene('家园界面')` —— 命中即**已在家园**，
   `then` 为空、整段进入链跳过（避免在家园里空点「家园」而误触其它按钮）。
   场景判据 = `and( any[一键种植,菜单], count[8钮, min:3] )`（scenes.json「家园界面」），
   **判据来源为用户口述**（右下角 快捷操作/种植箱/一键种植/离开/地图 + 左上角 菜单/奇妙花宝/园艺店）。
   > **为何迁移**（里程碑 80 B1 整改）：旧判据 `if_text(['菜单','离开','奇妙花宝'], region [0,0,0.25,0.16])`
   > 是**任一文本命中**语义 —— 闪耀变身页左上角自带「菜单」，孤钮即过（16:35 日志行 3361 实锤误判归位）。
   > 场景判据的「锚点 + 8钮≥3」结构化约束天然拒绝孤钮（16:35 日志 127 次判定零误判）；区域约束随之取消。
1. 未在家园时 `retry_loop(max_rounds=3)` 进入链：`do = [click_text('家园', mark:true) → sleep 1.5]`（里程碑 76 删 `fallback_rel 0.8719,0.9514`，OCR 未读到即脱困重试）；
   每轮无命中（即没点到「家园」）自动 `close_dialog()` 脱困一次再试下一轮（这一步就是「脱困一次-尝试」）。
2. `wait_scene('家园界面', timeout=5)` 等家园加载完成（**里程碑 80 由 wait_text 迁移**，超时语义不变=软失败）。
3. 复核 `if_scene('家园界面')`：仍没到家园 → `close_dialog` 脱困 → 再点一次「家园」→ 再 `wait_scene` → 再复核；
   两轮都没到就**如实报出**（不再假装成功，后续模块各自归位）。
4. 花田作业（浇水/施肥/授粉/收花）**待开发**，届时按「进入花田 → 作业循环(if_text 守卫+知识库兜底) → 关面板回家园」补充本节。

> 设计约定：种植/花田中「种植」按钮**不可点击**（会打开选种面板）；此机制由后续子流程实现。

> （2026-10-03 里程碑 73 实机修订：`close_family.png` 在子页恒 0.683 不命中、1080p 尺度超旧范围，改用 `click_rel`，见 4.1.2 第 5 步）。

3. `if_fraction`：读区域 (0.888, 0.7847) 的「今日浇水 X/3」，条件 `a<b`（未满）。
   - 满足则：OCR 点「浇水」`exact:true`（里程碑 76 删 fallback）→ **「恭喜获得」守卫（里程碑 78 N1）**：

     **延迟 ~4s 弹出、12s+ 不自动关**，先清弹窗再读计数（A10 闭环，旧 `click_rel(0.5,0.9389)` 在弹窗出现前盲点已删）
     → `store_fraction` 把当前浇水次数+日期写入 config（water_count），**避免同一天重复浇水**。
     > **`exact:true` 是必需的（2026-10-03 里程碑 73→74 两轮实机教训）**：关键字「浇水」是**子串匹配**，面板上含「浇水」的标签不止一个 ——

     > （**同屏多个含关键字标签时用 `exact`，勿逐个 `exclude`**）；**里程碑 76 起 fallback 已删** —— OCR 未读到按钮
     > 即由 retry_loop 脱困重试（真按钮实测 `浇水@rel(0.8484,0.6861)` 仅供参考，不再作点击兜底）。
4. **关闭摇钱树子面板（带区域守卫）**：`if_text(['今日浇水次数'], region_rel=[0.78,0.74,1.00,0.84])`
   （= 该子面板独有的「今日浇水次数：X/3」@abs(1067,565)）→ 命中才关闭。**关闭方式（里程碑 77 改模板，
   里程碑 81 C25 重裁修正）**：close_online_small（17×21）在面板顶部 ?/✕ 同款粉圈上无区分度（当晚 0.822
   误命中 (1082,181) 关不掉面板）→ 里程碑 75 直点过渡 → 里程碑 77 裁 `tree_close.png`（56×56 含白圈整体）
   → **里程碑 81 重裁 44×44**：旧模板误把**粉色呼吸光晕**裁入（动画相位波动 0.937~0.998，16:35 的 0.785

## 10. 识别与兜底机制

- 识别三通道：OCR 文字 → HSV 颜色（纯图形钮）→ 坐标锚点/模板匹配。
  **第四种判定/定位补充（里程碑 79）**：`locate_fine(kws, region_rel)` **滤色精识** —— 裁剪 region → 放大 ×2 →
  白字滤色（HSV V≥170 + S≤70 提取白字转黑字白底，彩底噪声归零）→ OCR → 坐标映射回全图。专治「白字彩底按钮
  被异常底色压低置信度」场景（如好友花园紫/蓝底「社交」）；仅在常规定位未命中后对小裁片运行（命中路径零开销）。
  pollin 的 `click_btn_fine` 在其上叠加**运行期按钮区域缓存**（真实命中点外扩 ±6%/±8%，内存字典不落盘；
  区域为动态推导非写死坐标，符合规则 6）。
- **手势原语 `swipe_rel`（里程碑 80）**：`swipe_rel(rx1,ry1,rx2,ry2,duration_ms=300)` —— 封装 MAA
  `post_swipe`，按相对坐标执行滑动（滚屏/拖动），尺寸未知先截图。
  > **规则 6 边界（用户 2026-10-06 明示裁定）**：滑动是**手势动作**，没有「识别目标」可定位 ——
  > 起终点是手势参数而非点击坐标，用相对坐标随分辨率自适应，**不属**被禁的「直接坐标点击」；
  > 点击类操作仍必须 OCR/模板/场景识别实时定位后才进行。当前唯一调用点 = pollin 底行补救段
  > （前置已确认 `in_list`，见 §4.2）。
- **场景判定与 `wait_scene` 多场景（里程碑 78 定立；里程碑 80 扩展）**：判据在 `flows/common/scenes.json`
  声明式 rule 条件树（`hit/any/all/count/absent/and/or/not`，叶子可带 `region_rel`）；引擎
  `judge_scene` + 步骤 `if_scene` / `wait_scene`。
  **`wait_scene` 的 `scene` 支持字符串或列表**（里程碑 80）：列表时每轮**一帧截图多场景共用**
  （每场景各一次 OCR，不逐场景重截屏），任一场景命中即成功并打
  `[等待成功] 场景『X』(多场景任一命中)`（指明走的哪条路）；超时路径与单场景完全一致（软失败语义保留）；
  单场景调用点行为逐字节不变。首个用例：startup `["户外主界面","签到中"]`（见 §1 第 4 步）。
- **`connect()` 连接即读尺寸（里程碑 80；里程碑 81 细化为两套）**：**先清零 `screen_w/h` 再探一帧**得
  **引擎工作区**（重连/换模拟器必拿当前值，全部相对坐标运算用它，日志 `[连接] 引擎工作区: WxH`）；
  再经 **adb 原生截图直读**（`exec-out screencap -p`，二进制安全、不经 MAA 缩放）得**实机分辨率**
  `display_w/h`（日志 `[连接] 实机分辨率: WxH / 引擎工作区: WxH (MAA 长边缩放)`；失败置 0 仅影响显示）。
  > **为何两套（里程碑 81 根因）**：MAA 截图管道有**长边 1280 缩放上限**（`set_screenshot_target_long_side`）
  > —— 实机 1920×1080 时引擎工作区实为 1280×720（同画面等比 0.667）。OCR/点击全部自洽工作在工作区内，
  > 相对坐标不受影响；但**展示**须用 adb 直读的实机值。设计取舍：不把 MAA 长边调到 1920（OCR 成本 2.25×）。
  WebUI 顶栏显示实机分辨率（`screen`；直读失败回退工作区），实机≠工作区时悬停提示工作区尺寸（`work` 字段）；
  三态：待读取 / 读取中… / 实机值。

> **`fail_flow` 步骤（2026-10-03 里程碑 69 新增）**：`{"type":"fail_flow","reason":"..."}` 抛 `FlowFailed`
> （继承 `Exception`），由 `run_module` 收成 `"fail"` 并 `report_failure` 登记（单跑流程时 `run_flow` 也接住，
> 不会漏成未捕获异常）。与 `StopRequested` 的区别：后者是「用户请求停止」（中断整轮、不算失败），
> `fail_flow` 是「本模块确实没做成」（如实认失败，交编排 `on_fail` 处置）。
> 用途：前置条件不满足时**主动中止**，避免带着错前提继续跑出一整轮假结果（如切号失败仍去点「登录」）。

> **`no_fallback` 步骤选项（2026-10-03 里程碑 69 新增）**：`click_text` / `click_template` 可用。
> 为 `true` 时**禁用整条缓存回退**（OCR/锚点/颜色全未命中就直接如实返回失败，不采信任何历史坐标盲点）。
> 用于「点错后果严重」的高危按钮。

> **`abort_on_fail` 步骤选项（2026-10-03 里程碑 69 新增）**：`click_text` / `click_template` / `click_account_tail`
> 可用（`click_text`/`click_template` 还可配 `abort_reason` 自定义上报文案）。为 `true` 时该步骤失败即
> `raise FlowFailed` 中止本模块，不再往下执行。

> **全局识别开关：`log_click_pos` / `use_cache_pos`（2026-10-03 里程碑 70 新增，均默认 `false` 关闭）**
> 位置 `data/config.json`，WebUI「使用界面 → 识别设置」面板可即时改。
> - `log_click_pos`（**记录按钮位置**）：`false` 时 `_log_click` 不把运行时点到的坐标写进知识库 `data/click_log.json`。
>   动机：历史坐标一旦写错，会被回退链反复放大成系统性误点（「切换账号」误登录即此链路），故默认不记。
>   **只 gate「引擎运行时的自动记录」**；人工标注（`/tpltool` 提交后写库）或直接编辑 `data/click_log.json`
>   是显式动作，不受此开关影响。
> - `use_cache_pos`（**使用缓存位置**）：`false` 时 `click_text` 不做「均值复核」（不拿历史均值 veto 本次 OCR 命中），
>   回退链也不再查自动学习到的历史坐标（`mean_rel` 均值 / `last_rel` 进程缓存 / 知识库 `rel`）→ 认不到就如实失败。
>   **注意：步骤里显式手写的 `fallback_rel` 仍生效** —— 与"自动学到的历史坐标"性质不同，全局开关**不得静默禁用**它。
>   步骤级 `no_fallback=true` 比此开关更严格：连显式 `fallback_rel` 一并禁用。
>   **里程碑 76 起 flows 中 `fallback_rel` 已按新规则（2026-10-04 用户规则：严禁直接坐标点击）全部清零（20 处）**，
>   引擎选项保留仅供历史兼容、**禁止新增**；存量直坐标（A 类）整改清单见 `_collab/inbox/zcode-developing/A类_直坐标模板化改造.md`。
> 两开关关闭时的提示各只打印一次（避免每次点击刷屏）。遗留完善项见 `docs/PROJECT_GUIDE.md` §5。

> **`ensure_home` 步骤（2026-10-02 里程碑 68 新增）**：调 `pollin.ensure_home(eng)`，确保回到自己家园主界面；
> 失败时 `report_failure` 如实报出（不假装成功）。用于「模块开头必须先在家园」的场景（如 §7 领取奖励）。

> **功能失败上报 / WebUI 弹窗（2026-10-02 里程碑 68）**：引擎新增模块级失败登记 `report_failure(module, detail)`
> （打印 `[失败] [模块] 详情` → 一眼可在日志搜到，同时进内存清单）。已埋点：`wait_text`/`wait_text_gone` 超时、
> `loop_text` 达上限、`retry_loop` 跑满未命中（可 `"report_fail": false` 免打扰）、`navigate` 未找到目标/轮数耗尽、
> `run_module` 流程文件缺失/模块异常、`fail_flow` 主动中止、`abort_on_fail` 步骤失败、`friend_pollin` 有类别未跑通、`ensure_home` 未归位。
> WebUI 通过 `GET /api/failures?after=<id>` **增量**拉取并在右下角弹出「功能失败提醒」（`POST /api/failures_clear` 清空）。

> **预览按需 OCR（2026-10-02 里程碑 68，性能）**：WebUI 预览帧 `GET /api/screen` **只回图像、不做 OCR**；
> 文字框拆到按需接口 `GET /api/ocr`，仅当用户勾选「OCR标注(按需)」或手动「取框」时才调用一次。
> 原实现每 1.5s 一帧都做全屏 OCR（单轮 1183 次），是「跑一轮 CPU >50%」的主凶
> （原注释写「与引擎抢 `ENGINE_LOCK`」不准确：`ENGINE_LOCK` 只用于引擎单例创建，真正的代价是预览每次自己
> `post_screencap` 与引擎争抢 ADB 控制器 —— 2026-10-03 里程碑 71 已修正注释并消除）。
> 另：标签页切到后台（`visibilitychange`）暂停预览与日志轮询。性能目标/预算的权威定义见 `docs/PROJECT_GUIDE.md` §11。

> **引擎侧性能优化（2026-10-03 里程碑 71，协作区 `zcode-20261003` 合并）**：① RapidOCR 每会话线程上限
> `ocr_threads`（默认 2，`0`=不限制；实测 720p 全屏 OCR 瞬时 ≈13 核 → ≈2 核、CPU 时间 −81%，**识别块零丢失**；
> **不下调检测边长**——实测 960/max 会在好友列表丢 5 块，影响采粉逐页读列表）；
> ② **同帧 OCR 复用** `_ocr_frame`（帧 blake2b-128 指纹，1280×720 约 3ms/次；`find_text`/`wait_text`/`wait_text_gone`/
> `click_account_tail`/`parse_fraction_at`/`parse_count_at`/`count_text`/`locate_anchor_offset`/`detect_scene` 全部走它，
> 画面一变指纹必然失效 → 等变化的循环不会被陈旧结果卡住）；
> ③ 运行期预览复用引擎 `last_frame`（2s 内只做 JPEG 编码、不碰 ADB；空闲期照旧自己截）。
> **对流程语义无影响**（flows/*.json 未改、步骤类型仍 24 种）；新增定位逻辑请走 `find_text`/`_ocr_frame`，勿裸调 `ocr_image`。

### 10.1 退出 / 脱困 / 归位约定（2026-09-29 里程碑 56）

**原则**：每个模块进入功能界面前，都应具备「页面不是预期界面时先退出、再尝试进入」的能力；
功能结束后应把画面**归位**到约定界面（户外主界面或家园），不能把残局丢给下一模块。

- **「脱困一次-尝试-不行再脱困」**：`retry_loop` 即此结构 —— 每轮跑 `do`，`mark` 步骤真实命中即成功退出；
  整轮无命中则 `fail_do`（未提供则自动 `close_dialog()`）脱困后进入下一轮；跑满 `max_rounds` 放弃、不抛错。
- **⚠ 硬约束**：`mark` **只对 `click_text` / `click_template` 生效**，`if_text` / `wait_text` **不能**作为
  retry_loop 的命中证据；且 `click_text` 走 `fallback_rel` 缓存回退时**不计入**命中
  （`_last_locate_source == "fallback"`）。故守卫一律写成「外层 `if_text` 守卫 + `wait_text` 等加载 +
  显式 `close_dialog`/点击重试 + 内层 `if_text` 复核」的组合。
- **⚠ `navigate` 的表达力限制**：它的 `mark_text` 同时是「探测器」和「点击目标」，所以
  **无法表达「已经在那儿→什么都不做」**；若目标界面的标记词恰好是个不该点的按钮（如「菜单」），
  navigate 会错误地点它。需要「已到位则跳过」时必须在外面套 `if_text` 守卫。
- **到位判据口径**：
  - **家园** = 左上角 `['菜单','离开','奇妙花宝']`（region `[0.0,0.0,0.25,0.16]`）；
  - **户外主界面** = 底部 `['社交','家园','仙境花园']`（region `[0.0,0.80,1.0,1.0]`）；
  - 两者**都算归位完成**，表达「或」用嵌套 `if_text`。
  - ⚠ **「社交」不足以判定主界面**（2026-10-02 里程碑 68）：**好友列表**底部导航同样有「社交」，只判「社交」会把列表
    误判成主界面。故 `pollin.in_home` 先 `in_list`（『删除好友』/『好友设置』）判否再看「社交」；脱困时若在列表，
    走 `pollin.leave_friend_list`（右上角关闭区 → 等列表消失 → 底部栏 [0.70,0.88,1.0,1.0] 找「离开」）。
- **如实报出**：脱困用尽仍未到位时**不得假装成功**（缓存回退尤其禁止当命中判据），
  要打印「仍未确认/放弃本轮」并把归位动作交给有自带归位链的后续模块。
- **共用预界面**：同一预界面下的多个子功能（如 §4.1.1 摇钱树 / §4.1.2 闪耀委托挑战）结束后
  **只关子面板、留在预界面**，下一个子功能直接复用，不退出到主界面再点开；模块末尾再加一道「收尾」清残留面板。
- **⚠ 模态对话框会吞掉一切点击**：某些对话框（如 §4.3 好友列表翻页的「跳转页签」）弹出后处于**模态**状态，
  此时点右上角、点底部导航、点关闭模板**全部无效**（实测 4 条路径全空转、画面一字未变）。
  故**脱困第一步必须是 `close_dialog()` 关模态框**，之后才做归位；否则后续所有点击都被吞。
  参考实现：`community_like.escape_to_main(eng)` = `close_dialog()` → `pollin.ensure_home(eng)` → 条件性「菜单→家园」兜底。
- **归位链优先复用**：模块级归位（关提示框/离开好友花园/关家族面板/右上角兜底）已由 `pollin.ensure_home` 实现，
  新模块直接复用，不重复造轮子。
- **⚠ 全屏子页的出口必须实机定位，不可想当然**（2026-09-30 里程碑 62；2026-10-03 里程碑 73 修订）：部分子页（如 §4.1.2 委托挑战）是**整屏 UI**，
  外壳右上角关闭钮会被内容层压住点不动，`close_*` 模板会恒不命中（`close_family` 在子页恒 0.683，且 1080p 尺度超旧范围）；
  出口具体位置**必须实机采集**——委托子页实测 `rel(0.9010,0.1065)`（**内容区右上角白色圆形粉花✕**），
  **不是**早期假定的左上角「返回」箭头（`(0.035,0.038)` 实为「家族」标题文字，点了无效，是 2026-10-03 卡死 40 分钟的根因）。
  判据用**该子页独有文字**（如委托子页 `['委托排行','距离结束']`）而非通用模板；退出时先点内容✕回到上一级面板，下一轮再关外壳。
  实现一律用 `eng.click_rel(...)`（项目「返回键已停用」约定，不用 `back()`）。
- **脱困点击必须复核画面变化**（2026-10-03 里程碑 73，A6）：退出/归位链每次点击后必须 `wait_screen_change` 确认画面真的切换，
  无效则升级下一策略；连续 2 次无变化如实快速失败并自动存证 `debug/escape_fail_*.png`（供 WebUI `/tpltool` 载入采出口控件）。
  「点了就当成功」是本项目卡死空转的主要来源（2026-10-03 家族界面卡死 40 分钟、`energy`/`claim` 全程陪跑）。
